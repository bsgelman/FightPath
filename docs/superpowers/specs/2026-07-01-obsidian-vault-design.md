# Design: Obsidian knowledge vault for FightPath ML

## Goal

Turn `/docs` into an Obsidian-browsable knowledge graph of research notes, cross-linked to
`/src` and to the existing evidence log (`RUNS.md`), with a periodically-regenerated index and
a durable convention (via `CLAUDE.md`) so future sessions check for an evidence trail before
model-behavior changes.

## Constraints (from user + existing repo conventions)

- Preserve all existing import paths, module dependencies, Git history.
- `RUNS.md` is already the canonical evidence log (dated entries: hypothesis → gate results →
  action). Do not fork it — new vault notes must point at it, not duplicate it.
- `architecture_spec.md` remains the single canonical architecture doc (per `CLAUDE.md`); not
  restructured into note fragments.
- BMAD tooling is already installed (`_bmad/`, `_bmad-output/{planning-artifacts,
  implementation-artifacts}`, currently empty) — a separate agentic doc-generation system.
- `.obsidian/` is a fresh vanilla config; `templates`, `backlink`, `graph`, `properties` core
  plugins are already enabled.
- `scripts/` naming convention: `NN_name.py` = numbered pipeline stage, `_name.py` = manual/
  periodic utility. A vault reindexer is the latter.

## Decisions (resolved via user Q&A, 2026-07-01)

1. **RUNS.md relationship — thin backlink layer.** RUNS.md stays the single source of truth for
   run history. A vault note carries `related_runs_entry: "RUNS.md#<anchor>"` in frontmatter
   instead of restating the entry's content.
2. **BMAD scope — unified indexing.** `Master_Index.md` also scans `_bmad-output/**/*.md` so
   BMAD-generated docs appear in the same graph, listed separately since they don't carry the
   vault's frontmatter schema.
3. **Retroactive scope — going forward only.** No frontmatter added today to
   `architecture_spec.md`, `RUNS.md`, or `outputs/reports/*.md` (100+ generated dated reports —
   machine output, not research notes). The convention applies to new notes in `docs/notes/`
   from this point on.

## Directory layout

```
docs/
  notes/                          # knowledge-graph nodes (research notes go here)
  templates/
    research-note-template.md     # YAML frontmatter template, wired into Obsidian Templates plugin
  Master_Index.md                 # generated by scripts/_reindex_vault.py — never hand-edited
  superpowers/specs/              # brainstorming-skill design docs (this file)
```

## Frontmatter schema (`docs/templates/research-note-template.md`)

```yaml
---
type: research | decision | evidence | reference
date: YYYY-MM-DD
model_version: v8.38 | n/a
status: draft | active | superseded | archived
related_code_files: []           # repo-relative paths
related_runs_entry: ""           # e.g. "RUNS.md#v838--2026-06-27"
tags: []
---
```

## `Master_Index.md` generation

Grouped by `type`, then by `model_version`. Includes a reverse-lookup section ("notes touching
`<path>`") built from `related_code_files` — this is the bidirectionality mechanism: notes link
to code via frontmatter, code "links back" to notes only through this generated reverse index,
**not** via comments injected into source files (keeps the vault non-invasive to `/src`).
A separate section lists `_bmad-output/**/*.md` files found (no schema validation applied to
those, since BMAD controls their format).

## `scripts/_reindex_vault.py`

- Walks `docs/notes/**/*.md`, parses YAML frontmatter.
- Missing/invalid required fields → warning printed to stdout, file still indexed (does not hard-fail).
- Walks `_bmad-output/**/*.md` for the BMAD section (path + title only, no frontmatter expected).
- Regenerates `docs/Master_Index.md` deterministically (sorted, so diffs are stable/reviewable).
- Manual/periodic trigger only — not wired into `dev.bat`, not a Gate, no CI hook.

## Obsidian wiring

Write `.obsidian/templates.json` to point the already-enabled Templates core plugin at
`docs/templates/`, so the frontmatter template is insertable via Obsidian's native template
command — not just a file the user copies by hand.

## `CLAUDE.md` addition

A short new section (matching the file's existing terse style):

```markdown
## Knowledge vault (Obsidian, /docs)
Research notes live in `docs/notes/` (frontmatter: type/date/model_version/status/
related_code_files/related_runs_entry/tags — template at `docs/templates/research-note-template.md`).
Index: `docs/Master_Index.md`, regenerate via `python scripts/_reindex_vault.py`.
RUNS.md remains the source of truth for run history; a vault note points at a RUNS.md entry via
`related_runs_entry` rather than duplicating it. Before a model-behavior change, check
Master_Index.md for prior evidence; if a proposed change lacks an evidence trail, ask before
proceeding.
```

This is what makes the "steward" behavior durable across sessions — a verbal agreement in one
chat doesn't persist; `CLAUDE.md` is loaded automatically every session.

## Explicit non-goals

- No retroactive frontmatter on existing docs (see Decision 3).
- No in-source-file comment pointers back to vault notes — reverse links are index-level only.
- No automated CI enforcement of "every model change has a note" — this is a check I perform
  manually per the CLAUDE.md convention, not a Gate E or pipeline hook.
- No migration of BMAD's existing artifact structure — indexed as-is.

## Testing / verification

- `python scripts/_reindex_vault.py` run against an empty `docs/notes/` produces a valid
  `Master_Index.md` with empty sections (no crash on zero notes).
- Add one sample note under `docs/notes/` with full frontmatter, one with a missing field, one
  malformed YAML file — confirm the script indexes the two valid ones, warns (not crashes) on
  the malformed one, and the reverse-lookup section correctly attributes `related_code_files`.
- Confirm `_bmad-output/` section renders even though those subfolders are currently empty.
